# POC application Mac (Tauri v2) — page Élections, présidentielles HdF

Date : 2026-10-06 · Agent : ingenieur-infra · Périmètre : emballage de la maquette `web/`
(Vite + React + TS) en application macOS, sans modification du code de la page.

## Résumé exécutif

- La chaîne fonctionne : `npm run tauri:build` produit un `.app` (4,85 Mo) et un `.dmg` (3,2 Mo) arm64, non signés (signature ad hoc du linker), qui s'ouvrent et affichent la page.
- Démarrage (ouverture → carte prête, 3 lancements) : 0,86 à 1,13 s en ligne ; hors ligne simulé, communes affichées en 1,3 s (3 780 polygones rendus, 47 tuiles refusées sans effet).
- Changement d'année : 29 à 58 ms jusqu'à l'image suivante (WebKit) ; mémoire : 257 Mo (empreinte cumulée des 4 processus), jusqu'à ~430 Mo après un long usage.
- Compilation : ~2 min la première fois, ~1,5 min ensuite (LTO) ; dossier `target/` 808 Mo (disque externe).
- Branche `poc/tauri` (non poussée). `tsc --noEmit` 0 erreur, `npm run build` OK, cargo 0 avertissement, `npm audit` 0 vulnérabilité. Aucun code Python modifié.
- Limites : arm64 seul, pas de capture d'écran (permission « Enregistrement de l'écran » absente), identifiant de bundle provisoire.
- Décisions attendues : Q1 compte Apple Developer, Q2 identifiant de bundle, Q3 universel ou arm64, Q4 mécanisme de mise à jour, Q5 poursuite du portage.
- Suite proposée : Mathias ouvre l'app et juge à l'œil (§ 5), puis décision Q5.

## 2. Mesures

Mac mini M4, macOS 27, build release arm64. Instrumentation temporaire (non commitée) : un
module mesurait dans la page et envoyait le résultat à un écouteur local `127.0.0.1:8765`
(ajouté à la CSP du seul build de mesure). Origine des temps : horodatage pris juste avant
`open -n` sur le `.app`.

| Mesure | Résultat |
|---|---|
| Taille `.app` | 4,85 Mo (binaire arm64 unique, ressources compressées) |
| Taille `.dmg` | 3,17 Mo (3 327 602 octets) |
| Démarrage à froid, en ligne (`open` → `idle` MapLibre, tuiles IGN comprises) | 1 127 ms (1er lancement), 868 ms, 864 ms |
| Dont `open` → début de navigation WebView | 550 ms, 314 ms, 301 ms |
| Démarrage hors ligne simulé (`open` → communes rendues) | 1 325 ms (1er lancement de ce build) ; `idle` à 1 465 ms |
| Changement d'année (clic → image suivante, 10 changements) | 29 à 58 ms, médiane ~39 ms |
| Mémoire (empreinte `footprint`, après 10 changements) | 257 Mo : app 43, WebContent 190, GPU 17, réseau 7 |
| Mémoire, instance restée ouverte plus longtemps | WebContent 369 Mo, app 44, GPU 19 (~435 Mo) |
| Compilation release | 1re : ~130 s dont 93 s cargo ; suivantes : ~90 s (LTO + `codegen-units = 1`) |
| Dossier `target/` | 808 Mo (sur le disque externe, via `CARGO_TARGET_DIR`) |

Hors ligne : simulé en retirant `data.geopf.fr` de la CSP (les requêtes de tuiles échouent
comme sans réseau ; couper le réseau du Mac aurait gêné les autres sessions). Résultat :
3 780 communes rendues (les 2 autres hors du cadre initial), 47 erreurs de tuiles absorbées,
page fonctionnelle. Le code de la maquette passe déjà `setPrete` sur `style.load` et non sur
`load` (`web/src/Carte.tsx`), d'où ce comportement. Dans ce build, la boucle de changements
d'année ne s'est pas terminée (attente de l'événement `idle` après clic) : le temps de
changement d'année hors ligne n'est donc pas mesuré ; à vérifier à l'œil (§ 5).

Le changement d'année est plus lent que dans Chromium (15-22 ms, rapport
`poc-interface-web-2026-10-06.md`) : moteur WebKit, et ici mesuré jusqu'à `idle`, qui a
coïncidé avec l'image suivante. Reste imperceptible.

## 4. Limites

1. **arm64 seul** : un binaire universel (Intel + Apple Silicon) demande
   `rustup target add x86_64-apple-darwin` et `tauri build --target universal-apple-darwin`
   (téléchargement de la cible, temps de compilation doublé). Non fait (Q3).
2. **Non signé, non notarisé** : signature ad hoc du linker uniquement. Une copie téléchargée
   est bloquée par Gatekeeper ; l'utilisateur doit passer par Réglages Système >
   Confidentialité et sécurité > « Ouvrir quand même ».
3. **Identifiant provisoire** `fr.ministere-info.desktop` : `fr.ministere-info.app` a été
   écarté (Tauri avertit qu'un suffixe `.app` entre en conflit avec l'extension des bundles).
   Le domaine `ministere-info.fr` n'est pas vérifié comme possédé (Q2).
4. **Pas de capture d'écran** : `screencapture` échoue (« could not create image from
   display ») faute de permission « Enregistrement de l'écran » pour le terminal ; aucune
   modification des permissions n'a été tentée. `docs/captures/poc-tauri/` n'est pas créé.
5. **Icône** : flèche ↘ conforme au chemin du design system (trait 3, extrémités carrées) ;
   l'extrémité carrée du trait diagonal dépasse légèrement l'angle de la pointe, visible en
   grand format. À juger à l'œil ; correction possible en raccourcissant le trait (écart à la
   spécification).
6. **Mises à jour** : aucune. Une nouvelle version = nouveau `.dmg` à redistribuer.
7. **Instance tierce observée** : `/Applications/Ministère de l'Info.app` (identifiant
   `fr.ministere-info.app`, identique au premier build de ce POC) tournait depuis 22:21:51 ;
   elle n'a pas été installée ni arrêtée par cet agent. Données associées :
   `~/Library/{WebKit,Caches}/fr.ministere-info.app` (~7 Mo). À supprimer si inutile.

## 6. Diffusion à un public restreint

1. **Signature et notarisation** : compte Apple Developer Program (99 USD/an), certificat
   « Developer ID Application », variables `APPLE_SIGNING_IDENTITY`, `APPLE_ID`,
   `APPLE_PASSWORD` (mot de passe d'application), `APPLE_TEAM_ID` en secrets ; Tauri signe et
   notarise pendant `tauri build`. Sans compte : diffusion possible mais contournement
   Gatekeeper manuel pour chaque utilisateur.
2. **Mises à jour** : plugin `tauri-plugin-updater` (clé de signature propre à Tauri, fichier
   `latest.json` publié en asset de GitHub Release), ou simple redistribution du `.dmg`.
3. **CI** : job `macos-latest` (arm64) dans `docker-publish.yml` ou un nouveau workflow,
   actions épinglées, `.dmg` publié en asset de release à côté de la base.
4. **Publication web en parallèle** : `npm run build` produit un site statique (`dist/`,
   chemins relatifs) hébergeable tel quel (GitHub Pages ou équivalent) ; même CSP à
   reproduire en en-tête HTTP. Les deux canaux partagent le code et l'export de données.
